# Объяснение для руководителя

## Что это

Небольшая система для строительной компании: **объекты** (стройки) и **задачи** по ним. Руководитель (постановщик) создаёт задачи и назначает исполнителей. Исполнители видят только свои задачи, берут их в работу и отправляют на проверку. Руководитель принимает задачу или возвращает на доработку с комментарием.

## Как пользоваться

1. Войти по email и паролю (аккаунты заводятся администратором, самoregистрации нет).
2. Постановщик: раздел «Объекты» → объект → «Новая задача» → выбор исполнителя.
3. Исполнитель: «Мои задачи» или объект → открыть задачу → кнопки «Взять в работу», «На проверку» и т.д.
4. В карточке задачи видна **история**: кто, когда и с какого статуса на какой перешёл.

## Как защищены данные

Данные лежат в облачной базе Supabase. Доступ настроен **в самой базе**, а не только кнопками в интерфейсе.

- Исполнитель **не может** прочитать чужие задачи, даже если попытаться обратиться к базе напрямую.
- **Нельзя** подделать историю статусов через приложение: клиенту разрешено только читать историю, писать её может только серверная логика базы.
- **Нельзя** перевести задачу в недопустимый статус «в обход правил» — проверка выполняется в базе при вызове специальной функции смены статуса.
- Секретные ключи администратора базы **не** попадают в сайт и в код на GitHub — на сайте только публичный ключ с ограниченными правами.

## Что исполнитель не может сделать

- Создавать или удалять объекты и задачи.
- Менять исполнителя, название или описание задачи.
- Принимать свою задачу или возвращать чужую на доработку.
- Видеть задачи других исполнителей.
