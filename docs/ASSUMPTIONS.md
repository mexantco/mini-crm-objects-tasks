# Решения и допущения

## Принятые решения

- **Стек:** Vite + React + TypeScript, Tailwind + shadcn/ui, Supabase Auth + Postgres.
- **Смена статуса:** только RPC `change_task_status`; прямое изменение поля `status` блокируется триггером.
- **История:** при создании задачи пишется первая запись («→ Новая»); дальнейшие переходы — в RPC и при создании.
- **Редактирование задачи:** постановщик может менять поля через UPDATE, пока статус не «Принята»; исполнитель не редактирует поля задачи.
- **Удаление объекта:** разрешено постановщику; если есть задачи, сработает ограничение FK (`on delete restrict`) — объект нужно сначала очистить от задач.
- **Роли:** задаются в таблице `profiles` вручную в Supabase после создания пользователя в Auth.
- **UI:** минималистичный B2B-стиль (серый + оранжевый акцент), без тёмной темы и без realtime.

## Не успели / вне объёма 2–3 ч

- Редактирование и удаление задачи отдельными формами в UI (создание и статусы — есть; удаление задачи можно добавить одной кнопкой).
- Автоматический seed через скрипт (есть шаблон SQL).
- E2E-тесты и автоматическая проверка RLS в CI.
- Видео-демо (есть текст для руководителя в `docs/HANDOFF.md`).
